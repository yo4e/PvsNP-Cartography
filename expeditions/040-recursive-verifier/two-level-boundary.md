# The first two-level row is not a Boolean pass/fail flag

At (k,a)=(8,3) the public seed z consists of a four-bit low part u and a four-bit high part v. The selected outer row v has dimension 7. At that child the inherited seed is u+16f, for each outer fresh word f=0,…,7. Its three low bits b=u mod 8 select four column labels b+8h. Its four high bits select eight distinct row labels j=bit₃(u)+2f. The union over all fresh tapes checks **eight inner rows of one parity**, and four inner columns, for this u. Outer column children have dimension 4, hence terminate. These identities follow from the fixed bit partitions and do not require field arithmetic.

Take the zero root and zero auxiliary cells. Flip one nonzero extension symbol of inner row j=3 inside outer row v=4, at within-inner-row slot 8. At this slot its auxiliary-direction bits are nonzero and its common-rectangle selector is zero. The symbol belongs to neither the inner parent nor the inner column rectangle; that address retains both row labels and has no aliases in any other subtree. Only inner row 3 fails (63 unchanged zeros rule out degree <8 on its 64 distinct points). All columns and all other relevant rows pass. The very same outer row 4 passes for low parts 0,…,7 and fails for 8,…,15. Thus the precise rejecting public seeds are 72,…,79. The [schedule program](verify_two_levels.py) enumerates all 256 seeds. It checks the route combinatorics; it does not implement the entire k=8 field verifier.

This witness refutes treating success on a *selected* row at k=8 as one row-wide flag. Its root distance is zero, so it gives **no counterexample** to a lower bound by root distance. For a fixed outer row, a uniform u induces two independent indices: the inner row parity and the column residue modulo eight. The probability that all bundled tests pass there is (#parities whose eight rows all pass)/2 times (#residues whose four columns all pass)/8. Joining this event with the outer column tests requires the same u. The overlap of the passing residues across levels matters. This is the first subproblem for [Issue 30](https://github.com/yo4e/PvsNP-Cartography/issues/30).
